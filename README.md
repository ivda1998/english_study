# 영어 60분 — 중3 영어 학습 플랫폼

읽고 → 생각하고 → **영어로 짧게 표현하는** 쪽에 무게를 둔 개인 학습 웹앱입니다.
말하기를 많이 시키기보다, 잘 읽은 다음 그 내용을 자기 말로 짧게 꺼내는 흐름으로 설계했습니다.

브라우저만 있으면 되고, 학습 기록·녹음은 **모두 그 기기 안에만** 저장됩니다. 서버도 로그인도 없습니다.

## 하루 60~70분, 주 5일

| 요일 | 어휘 | 문법·구문 | 독해 | 듣기 | 말하기 | 합계 |
|---|---|---|---|---|---|---|
| 월 | 15분 | 20분 | 15분 | 10분 | 10분 | 70분 |
| 화 | 15분 | 15분 | 15분 | 10분 | 15분 | 70분 |
| 수 | 15분 | 20분 | 15분 | 10분 | 10분 | 70분 |
| 목 | 15분 | 15분 | 15분 | 10분 | 15분 | 70분 |
| 금 | 15분 | 15분 | 15분 | 10분 | 15분 | 70분 |

타이머는 압박이 아니라 안내입니다. 멈춤·건너뛰기·연장이 자유롭고, 못 채웠다고 벌점이 붙지 않습니다.
하루를 빠져도 밀리지 않고, **아직 끝내지 않은 날**부터 이어서 하면 됩니다.
주말은 복습과 "즐기는 영어" 20~30분이면 충분합니다.

## 말하기 4단계 (하루 10~15분)

1. **따라 읽기 3분** — 그날 지문에서 고른 2~3문장을 듣고 → 멈추고 → 따라 읽습니다. 발음 교정은 하지 않습니다.
2. **문장 바꿔 말하기 3분** — `I like [math] because it is [interesting].` 처럼 한 부분만 바꿔 3~5번.
3. **질문에 답하기 3분** — 질문 카드 5개. **한 문장으로 답해도 성공**입니다.
4. **1분 말하기 3~5분** — 키워드 5개만 보고 말합니다. 목표 시간이 30초 → 1분 → 1분 30초로 스스로 올라갑니다.
   말하기가 15분인 **화·목·금에만** 열립니다(주 3회).

여기에 두 가지가 더 붙습니다.

- **수학으로 말하기** (주 1회) — 문제 풀이를 `First / Then / Finally` 로 설명하고, 주차가 올라가면 확장형 문장으로 넘어갑니다.
- **지문 설명하기** — 오늘 읽은 글을 자기 말로 설명합니다. 겨울방학 목표(1~2분 설명하기)로 가는 연습입니다.

## 목표

| 시기 | 목표 | 앱에서 재는 방식 |
|---|---|---|
| 중3 2학기 | 30초~1분 말하기가 부담스럽지 않게 | 1분 말하기 10회 이상, 최근 5회 평균 45초 이상 |
| 겨울방학 | 지문을 읽고 1~2분 자기 말로 설명 | 지문 설명하기 5회 이상, 최근 3회 평균 90초 이상 |
| 고1 | 준비한 내용을 발표하고 짧게 대답 | 누적 40회 이상, 최근 5회 평균 90초 이상 |

정확도 점수는 어디에도 없습니다. **말했다는 사실과 발화 시간**만 기록합니다.

## 화면

- **오늘** — 오늘 할 학습, 복습할 단어 수, 목표 진척도
- **6주 계획** — 시간표와 30일 전체 진도
- **복습** — 어휘 SRS(Leitner 5단계), 오답 노트, 주말 "즐기는 영어" 기록
- **성장 기록** — 말하기 시간 추이, 영역별 공부 시간, 녹음 다시 듣기
- **부모** — 주간 요약, 코칭 원칙, 오늘 물어볼 영어 질문 5개
- **설정** — 목소리·속도, 학교 단어장 넣기, 주차 콘텐츠 가져오기, 백업

## 콘텐츠

6주 × 5일 = **30일치**가 들어 있습니다. 하루에 어휘 10개, 문법 포인트 1개와 문항 6개,
지문 1편과 문항 4개, 듣기 대화와 받아쓰기, 말하기 4단계입니다.
모든 문항에 한국어 해설이 붙어 있습니다.

**지문은 기출이나 교재에서 가져온 것이 아니라 이 저장소를 위해 직접 쓴 글입니다.** 그래서 공개 배포에
저작권 문제가 없고, 그날 문법 포인트가 지문 안에 자연스럽게 들어가도록 맞출 수 있습니다.
소재가 실제 연구인 경우에는 `passage.source`에 출처를 적고 지문 아래에 함께 보여줍니다.
읽은 내용을 사실로 받아들이게 되므로, 근거를 확인할 수 있어야 하기 때문입니다.

학교 교재나 기출로 공부하고 싶다면 **설정 → 주차 콘텐츠 가져오기**를 쓰세요.
그렇게 넣은 콘텐츠는 그 기기에만 저장되므로 배포되지 않습니다.

학교 교재를 얹는 방법은 두 가지입니다.

1. **설정 → 학교 단어장 넣기**: `단어 / 뜻` 을 줄 단위로 붙여넣으면 복습 목록에 바로 들어갑니다.
2. **설정 → 주차 콘텐츠 가져오기**: `src/content/README.md` 형식의 JSON을 넣으면 빌드 없이 해당 주차를 대신합니다.

## 개발

```bash
npm install
npm run dev              # 개발 서버
npm run validate:content # 커리큘럼 검증 (30일 스키마·시간표·주제·정답)
npm test                 # 단위 테스트 74개
npm run build            # 검증 → 타입체크 → 빌드
npm run e2e              # Playwright: 하루 세션 완주, 진도 유지, 마이크 폴백, 모바일 폭, 밑줄 표시
```

`main`에 푸시하면 GitHub Actions가 테스트를 돌리고 GitHub Pages로 배포합니다.

저장소를 새로 만들었다면 **처음 한 번은 사람이 설정을 만져 줘야 하고, 순서가 중요합니다.**
워크플로 토큰 권한 밖이라 자동화할 수 없고, 안 하면 빌드가 전부 통과하고도 배포만 멈춥니다.

1. **Settings → General → Default branch** 를 **`main`** 으로. **Pages를 켜기 전에** 합니다.
2. **Settings → Pages → Source** 를 **GitHub Actions** 로.
   안 하면 `configure-pages` 단계에서 `Get Pages site failed` 로 멈춥니다.

순서가 바뀌면 한 단계가 더 필요합니다. Pages를 켤 때 `github-pages` 환경이 만들어지면서
**그 시점의 기본 브랜치 이름이 배포 브랜치 규칙에 그대로 박히고**, 나중에 기본 브랜치를 바꿔도
따라오지 않습니다. 이 경우 `deploy` 잡이 러너를 받기도 전에 거부되고 **로그가 아예 남지 않아**
원인이 보이지 않습니다. **Settings → Environments → github-pages → Deployment branches and tags**
에서 규칙을 `main` 으로 고치거나 제한을 없애면 됩니다.

## 부모가 도와줄 때

- 문법이 틀려도 **바로 지적하지 않습니다.** "아, 수학이 좋아서 그렇구나" 하고 내용에 반응해 주세요.
- 끝까지 말한 뒤에 **딱 하나만** 고쳐 줍니다.
- 길게 말하라고 하지 않습니다. 한 문장도 성공입니다.
- 발음은 건드리지 않습니다. 따라 읽기의 목표는 정확한 발음이 아니라 소리 내는 것입니다.

같은 내용이 앱의 **부모** 화면에도 항상 떠 있습니다.
